# Windows Process Execution Investigation — Rules 92032 & 92052

## Overview

This investigation analysed Windows process execution alerts generated by Wazuh.

The investigation focused on:

* Suspicious CMD execution
* Abnormal CMD execution
* Parent-child process relationships
* Command-line analysis
* Application context
* Event correlation

The objective was to determine whether the detected command execution represented malicious behaviour or legitimate application activity.

---

## Detection 1 — Suspicious Windows CMD Shell Execution

**Rule ID:** 92032

**Severity:** Level 3

**Description:** Suspicious Windows cmd shell execution

One of the investigated events involved:

```text id="0ql2hr"
Image:
C:\Windows\System32\cmd.exe

User:
ebenezer\ebene
```

The detection indicated that CMD execution matched the conditions defined by the Wazuh rule.

However, the rule itself did not establish that the command execution was malicious.

---

## Detection 2 — Abnormal Process Starting CMD

**Rule ID:** 92052

**Severity:** Level 4

**Description:** Windows command prompt started by an abnormal process

Further investigation showed that the CMD process was launched by Google Chrome.

```text id="t3uv3p"
Parent Image:
C:\Program Files\Google\Chrome\Application\chrome.exe

Parent Command Line:
"C:\Program Files\Google\Chrome\Application\chrome.exe"
--no-startup-window /prefetch:5
```

The process relationship was:

```text id="tyb1sg"
chrome.exe
    ↓
cmd.exe
```

---

## Detection 3 — Adobe Chrome Native Messaging Host

Further investigation showed that CMD launched an Adobe Acrobat native messaging component.

```text id="j6cmxz"
Image:
C:\Program Files\Adobe\Acrobat DC\Acrobat\Browser\
WCChromeExtn\WCChromeNativeMessagingHost.exe

Parent:
C:\Windows\System32\cmd.exe

User:
ebenezer\ebene
```

The complete process chain was therefore:

```text id="q8a9z7"
Google Chrome
      ↓
cmd.exe
      ↓
Adobe Acrobat Native Messaging Host
```

---

## Command-Line Analysis

The CMD command line included:

```text id="xq7p4n"
C:\Windows\system32\cmd.exe /d /s /c
"C:\Program Files\Adobe\Acrobat DC\Acrobat\Browser\
WCChromeExtn\WCChromeNativeMessagingHost.exe"
chrome-extension://efaidnbmnnnibpcajpcglclefindmkaj/
--parent-window=0
```

The command also used Chrome native messaging named pipes:

```text id="5f0z7e"
chrome.nativeMessaging.in.*
chrome.nativeMessaging.out.*
```

This provided additional context indicating communication between Chrome and the Adobe native messaging component.

---

## Event Correlation

Multiple Rule 92032 and Rule 92052 alerts occurred around the same time.

Rather than treating every alert as a separate incident, the events were correlated using:

* Timestamp
* User account
* Parent process
* Child process
* Command line
* Application path

This revealed that several detections were associated with the same Chrome/Adobe process execution chain.

---

## Investigation Findings

The following evidence supported a benign assessment:

### 1. Legitimate application paths

The processes were located under expected application directories:

```text id="ykly3d"
C:\Program Files\Google\Chrome\
C:\Program Files\Adobe\Acrobat DC\
C:\Windows\System32\
```

### 2. Recognisable software

The processes belonged to:

* Google Chrome
* Microsoft Windows
* Adobe Acrobat

### 3. Consistent process relationship

The observed process chain was:

```text id="5c3bwu"
Chrome
 ↓
CMD
 ↓
Adobe Acrobat Native Messaging Host
```

### 4. Previously observed behaviour

The same Chrome/Adobe native messaging behaviour had previously been investigated in the SOC laboratory and was assessed as legitimate application activity.

---

## Detection vs Evidence

This investigation demonstrated an important SOC principle:

> A detection is not the same as proof of malicious activity.

Rule 92032 identified CMD execution as suspicious according to its detection logic.

Rule 92052 identified CMD as being started by a process considered abnormal by the detection logic.

The underlying evidence was then used to determine what actually happened.

The parent process, child process, command line, user account, executable paths and application context provided more useful information for the final assessment.

---

## Classification

**🟢 Benign / Expected Activity**

---

## Key SOC Lessons

1. Do not classify an event as malicious based solely on the rule description.
2. Investigate the parent process responsible for launching a suspicious process.
3. Analyse the complete process tree where possible.
4. Examine command-line arguments to understand process behaviour.
5. Check whether executable paths belong to legitimate applications.
6. Correlate alerts occurring at the same time.
7. Previous observations can provide useful context.
8. Low or medium severity alerts can still require investigation.
9. High severity alerts do not automatically prove malicious activity.
10. Evidence should determine the final classification.

---

## Analyst Conclusion

The investigated Rule 92032 and Rule 92052 alerts initially indicated suspicious or abnormal CMD execution. Further process-tree and command-line analysis showed that Google Chrome launched CMD, which in turn launched the Adobe Acrobat Chrome native messaging host. The executable paths, application context, command-line parameters and previously observed behaviour supported a classification of benign/expected activity.

The investigation demonstrated the importance of analysing process relationships and supporting evidence before making a final security determination.
